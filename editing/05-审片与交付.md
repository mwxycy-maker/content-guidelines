# 05 审片、预览与交付

## 每段审片

- 先截开头、关键词、转场前后、结尾等关键时间点的静帧，再在浏览器完整播放。查看画面和口播是否对应，提示框是否指向正确素材，字和字幕是否清楚、完整、不压人脸或主播圆窗。
- 逐句听口播和字幕：实义无误删、无漏字、无错位或重叠；明显超过约 0.5 秒的空停顿已处理，有意保留的停顿能看出目的。
- 检查比较镜头的顺序、角度、运动方向和时长；新元素进场时构图有让位，镜头交接无空白帧。检查 BGM 换段、音效与动作、口播响度。
- 预览要能播放、暂停、拖动和跳镜头；源视频 seek、定格与变速要实测。缓存可能掩盖解码失败，切点处要看真实帧。HTML 录制素材还要扫黑帧、检查首帧和最后一帧；有问题回看原素材和代理映射。
- 手机预览时检查文字大小与阅读时间。屏幕上看得清不等于手机上看得清。

## 修改和交付

- 先交前约 30 秒定方向，之后按 30–45 秒一段回收反馈。修改后只重建受影响的数据或音轨，再刷新浏览器审片。默认交可编辑工程和网页预览；用户明确要求导出时，才运行视频导出器。
- 当期仓库提交必要的工程代码、字幕和时间线数据、便携素材、音效、可合法使用的字体与配乐、混好的预览音轨。不要默认提交本地高清原片、个人绝对路径、缓存、临时导出副本或最终成片。要让另一个环境能打开预览并定位素材；本地高清可通过映射覆盖便携素材。
- 用户明确要求导出后，先逐项核对高清源和映射，再核对输出倍速、分辨率、音画时长与文件可播放性。`web-player` 的 2560×1440 输出来自 1920×1080 逻辑画布放大，不能当作原生 2K 细节。
- 发给阿亮的单个文件小于 30 MB；超过时先给 720p 预览，原画质按当期约定放到 GitHub。代码若须在 GitHub 仓库首页可见，要确认最终落在默认分支。

## 常见问题的检查方向

| 现象 | 先检查 |
|---|---|
| 浏览器预览黑屏或“无法解码” | 素材文件是否存在、浏览器是否支持编码、代理映射是否更新；新素材接入后是否重启服务 |
| 定格或变速素材来回跳 | 素材播放速率是否传给播放器；定格和片尾停帧要使用 `rate = 0` |
| 转场处短暂空画面 | 上一镜退场和下一镜进场是否有接力；是否过早移除当前画面 |
| 截图文字模糊或被裁 | 源素材分辨率、裁切范围、透视幅度；必要时高清重排并逐行核对 |
| 导出与预览不同 | 任意时间取帧能否稳定复现、随机种子是否固定、源视频 seek 是否准确、是否把预览代理错当高清源 |
