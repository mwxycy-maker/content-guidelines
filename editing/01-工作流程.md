# 01 工作流程与时间线

## 开工

1. 读当期分镜、口播、素材清单与交付约定；先检查已有工程和播放器能否复用。疑问应定位到具体镜头和文件，再集中确认。
2. 默认交付可编辑的 HTML + Canvas 工程和浏览器预览；浏览器要能播放、拖动、跳镜头和逐帧查看。只在用户明确要求成片时导出 MP4，包括测试片。
3. 校对口播、建立有时间的字幕源；每一句确定对应画面。先用几张关键静帧确认视觉方向，再做整段。
4. 先交前约 30 秒确认方向；后续按 30–45 秒一段推进。每段完成后查看关键帧并播放，记录反馈并应用到后续段落。
5. 用户按“第 N 段”反馈时，先对照播放器中的分段序号与实际镜头内容，避免把它误当成分镜表行号。

## 一条统一时间线

- 保留原录音、原转写和逐字时间。`pieces` 记录从源音轨取哪一段、放到成片哪里；镜头、口播、人声、字幕和关键词事件都使用同一映射。
- 口播删去 `[a,b]` 后，后续事件整体前移 `b-a`。删除字幕文字不会剪掉音频；只改画面镜头长度也不会自动改变音轨。
- 用“第几句 + 哪个词”作为动画、音效和画面动作的事件锚点。说话或剪停顿后统一重建映射，避免散落的绝对秒数失效。需要动作预热时，入场可比词提前约 0.1–0.35 秒；重击与画面落点同帧。
- 对画面修改只刷新场景；对字幕文字和断句修改只重建字幕数据；删改口播或变速时重建时间线、字幕、事件并重新混音；改 BGM 或音效只重混。预览时不整片编码。

## 分工

- 整片的口播、字幕、混音与浏览器审片沿用网页工程；新项目可从本仓库 [`web-player/`](../web-player/README.md) 起步。已有可用项目先复用其流程。
- 花字、图标动效、信息图、标题和转场可做成独立 HyperFrames 片段：先交 HTML 预览，确认要出片后再渲染成素材放入工程。片段内动画要能按任意时间定位。
- 当期仓库放台词、素材、镜头、混音和可编辑工程；跨项目规则留在这里。交付文件范围见 [05](05-审片与交付.md)。
