# 03 画面、素材与动效

## 口播带动画面

- 每句先定对应画面：口播提到的对象出现时才展示，不提前揭示后文。讲解开头还未说到具体操作时可先保留全屏口播，说到操作再进录屏。
- 同一组比较素材要保持镜头角度、运动方向、播放速度、出场时间和屏幕顺序一致；元素实际大小不一时调到可比。口播点到哪个对象，就让它成为当前视觉重点。
- 演示刚出现时尽量居中、放大；有新信息进场再平滑让位，撤走后可回到主位。画中画主播放在空角，不遮挡内容或字幕。信息量足、清晰的素材可以全屏；模糊低清素材缩小放进合适的边框，不拿模糊放大版做背景。

## 文字和素材处理

- 手机可读是硬要求。画面只放有助于理解的字幕、必要名称或数据、单独出场的大标题；手机看不清的描述性小字、小标签、小数据牌一律不用。风格样片中的英文副标题、装饰性小标签不能直接搬入本片。大标题要给独立的口播停顿，不压人脸或素材重点。
- 裁掉素材自带字幕、水印、黑边和空白；台词用本片字幕重打。截图、录屏要突出被讲到的内容，可用裁切、推近、压暗其余区域和高亮扫过。文字截图若放大后发糊，优先高清重排或换更清楚的素材；不要为了透视效果牺牲可读性。
- 高亮框、提示圈、连线和数据标记只在口播讲到对应部位时出现；逐个检查框是否真的对准画面。文字或连线穿过人物时，按需要把它放在人像层后方。表示故障、风险、不可用时优先选与问题对应的图形和轻动效，避免反复用大红叉盖住内容。

## 动效的制作顺序

1. 先定动效的表达目的，再选运动方式。可以参考 [video-shotcraft 镜头库](https://github.com/Vincentwei1021/video-shotcraft) 的样片和参数，但选择标准始终是动作语义、段落情绪、口播时间能否匹配。库里没有合适的就复用现有组件，再不合适才设计新动作。字体、配色和文案全部按本期视频重做。
2. 动画片段优先做成 HyperFrames composition（HTML + GSAP）。写暂停的时间线，使任意时间点都可定位；先放进可拖动的 HTML 预览，用户确认要出片后才渲染为 MP4 或透明 WebM，再作为素材接入整片的 [`web-player/`](../web-player/README.md) 工程。
3. 动画只依赖当前时间，不依赖上一帧、实时时钟或不固定的随机数。开始、结束与口播关键词事件相连，口播改动后统一重排。镜头交接时让上一镜退场与下一镜进场适当重叠，检查有无空帧。
4. 一段只留一个高能动效重点，其余动作让位。入场约 0.55–0.75 秒、退场约 0.3–0.55 秒、重新构图约 0.6–0.7 秒可作初始值；换成真实文案和素材后必须预览微调。

| 画面意图 | 可选动作方向 |
|---|---|
| 普通标题或章节切换 | 低能量滑入、模糊到清晰、简洁字卡 |
| 强调关键词或结论 | 高亮扫过、描边填充、一次重击落位 |
| 一组素材入场 | 卡片逐张进入，间隔与口播或音乐节拍一致 |
| 指向界面上的一处 | 轻推镜、括号扫描或局部高亮，避免大框遮挡信息 |
| 数字揭晓或过程变化 | 数字随口播增长，到位后留出阅读时间 |
| 转场或片尾 | 根据叙事强度选擦除、隐藏切点、收束画面，不为炫技加动作 |

## HTML 演示素材

需要把多个网页演示做成可比较的素材时，先确定同一机位、比例、运动方向、速度和起始时刻；场景大小不同只调取景中心和距离。录制时固定随机种子，用假时钟逐帧推进页面动画，避免机器慢导致实时录屏掉帧。录制前先截样帧检查机位与多余的按钮、面板；录完逐帧检查突发黑帧、首尾帧和浏览器解码结果。高成本录制先做一小段验证，合格后再批量生产。
