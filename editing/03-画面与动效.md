# 03 画面、素材与动效

## 口播带动画面

- 每句先定对应画面：口播提到的对象出现时才展示，不提前揭示后文。讲解开头还未说到具体操作时可先保留全屏口播，说到操作再进录屏。
- 同一组比较素材要保持镜头角度、运动方向、播放速度、出场时间和屏幕顺序一致；元素实际大小不一时调到可比。口播点到哪个对象，就让它成为当前视觉重点。
- 演示刚出现时尽量居中、放大；有新信息进场再平滑让位，撤走后可回到主位。画中画主播放在空角，不遮挡内容或字幕。信息量足、清晰的素材可以全屏；模糊低清素材缩小放进合适的边框，不拿模糊放大版做背景。

## 文字和素材处理

- 手机可读是底线。默认只放必要的字幕、名称和单独出场的大标题；不堆描述性小字、小标签、小数据牌。大标题要给独立的口播停顿，不压人脸或素材重点。
- 裁掉素材自带字幕、水印、黑边和空白；台词用本片字幕重打。截图、录屏要突出被讲到的内容，可用裁切、推近、压暗其余区域和高亮扫过。文字截图若放大后发糊，优先高清重排或换更清楚的素材；不要为了透视效果牺牲可读性。
- 高亮框、提示圈、连线和数据标记只在口播讲到对应部位时出现；逐个检查框是否真的对准画面。文字或连线穿过人物时，按需要把它放在人像层后方。表示故障、风险、不可用时优先选与问题对应的图形和轻动效，避免反复用大红叉盖住内容。

## 动效的制作顺序

1. 先按画面意图挑动作：阿亮 2026-11-04 指定优先查 [video-shotcraft 镜头卡](https://github.com/Vincentwei1021/video-shotcraft)，看完整配方和样片，再结合本期视觉规范改字体、配色、文案与素材。卡不合适时复用已有组件，仍不合适再设计新动作。卡的时长、能量和“全片最多几次”要控制；一段只留一个高能重点。
2. 对动画片段，默认采用 [HyperFrames 工作流](https://github.com/mwxycy-maker/jianjiguize/blob/c698d5a4e36d6b1354ad19a979a72b800cc106d9/HyperFrames模板/README.md)：先可拖动的 HTML 预览，确认后才渲染为可用素材。整片仍由网页剪辑工程预览。遇到难以移植的镜头卡，原规则允许单段用其 Remotion 示例渲染并说明原因。
3. 动画应由当前时间决定，支持任意拖动、逐帧和重复取帧。开始、结束与关键词事件相连，避免口播改动后画面脱节。镜头交接时让上一镜退场与下一镜进场适当重叠，审查有没有空帧。
4. 入场、移动、退场按内容安排；`jianjiguize` 的实战参考是入场约 0.55–0.75 秒、退场约 0.3–0.55 秒、重排约 0.6–0.7 秒。换用真实文案和素材后必须重新预览，不能机械照搬参数。

## HTML 演示素材

需要把多个模型生成的网页演示做成可比较的素材时，统一机位、比例、速度和随机种子；用假时钟逐帧录制，先截样帧检查多余界面元素，再录完整片。录后检查黑帧和实际解码；这是一类专项制作方法，脚本与机位配置见 [jianjiguize 07](https://github.com/mwxycy-maker/jianjiguize/blob/c698d5a4e36d6b1354ad19a979a72b800cc106d9/规则/07-HTML演示录制.md)。
