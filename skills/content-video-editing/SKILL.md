# 通用视频剪辑规则

这套规则来自用户的 `content-guidelines`，适用于不同视觉风格。优先级：**当前任务的明确要求 → 本 Skill 和 `editing/` 的通用剪辑规则 → 风格 Skill 参考**。通用规则决定整个视频的基调、制作流程和硬性指标。若要特定账号风格，另外读取用户点名的一个风格 Skill；它只供参考，不能改写通用规则。未点名时，不自行套用或混合多个账号风格。历史案例中的固定配色、具体歌曲、模型名单和旧版限制不自动成为本期规则。

本文件是便于安装的执行摘要。仓库可访问时，按任务读取 `editing/` 的对应细则；同一条通用规则在两处出现差异时，以仓库 `editing/` 的较新版本为准。

当风格 Skill 给出不同的字幕行长、气口松紧、画面标签、BGM 换曲方式或响度时，按本通用规则执行。风格样片数值只用来理解该风格，不作为新视频的硬指标。30–45 秒是审片交付分块，BGM 按实际话题或章节切换。

## 开工与时间线

- 先读当期分镜、口播、素材清单和已有剪辑工程，核对交付形式。默认交可编辑工程及浏览器预览；只有用户明确要求导出时才编码成片，包括测试片。
- 校对口播转写，保留原录音、原转写和逐字时间。每一句确定对应画面。先用关键静帧和前约 30 秒确认方向，再按约 30–45 秒一段制作、审片、回收反馈。
- 口播、人声、字幕、镜头和关键词事件共用时间映射；剪口播、补录或变速后同步重建。只改字幕文字时保持原音轨和画面节奏，只重建受影响的数据。

## 口播与字幕

- 明显超过约 0.5 秒的空停顿要压缩或用转场覆盖。仅剪停顿时不剪字，切点试听是否自然；有意给笑点、标题或演示留的停顿写进时间线。正常呼吸是否保留，按听感和本期节奏判断，不批量删除。
- 字幕按实际说出的话校对。结合语境删无意义语气词和重复起句，不做全局字符删除。显示字幕不带句读标点；顿号改成一个半角空格，换条处不用补空格；型号、数字和英文内部有意义的符号照留。
- 一条字幕一个意群，问答分开；不拆词、品牌名或数字单位。按手机可读性排版，通常一行约 8–16 个汉字，语义完整优先。保留字使用原时间戳；交付前逐句听看是否漏字、错位、重叠或出画。

## 画面与动效

- 口播点到什么，画面才出现什么。同组比较保持机位、方向、顺序和相对大小一致。新元素出现时重新构图；画中画不得遮挡内容或字幕。
- 屏幕文字必须有助于理解且在手机上可读；手机看不清的说明性小字和小标签不用，即使风格样片里有。素材自带字幕、水印、黑边和空白须处理。文字截图放大后发糊时换清楚素材或高清重排。
- 动效优先查用户指定的 video-shotcraft 镜头卡，确认语义、能量和时长是否合适；再考虑已有组件或自制。单独动画片段优先用 HyperFrames，先交可拖动 HTML 预览，确认要出片后再渲染进整片工程。动效按时间定位，能任意拖动和逐帧复现。

## 音乐、音效与混音

- BGM 按段落情绪选并在话题转换时设计换曲。换歌明确上一首怎么停、中间用什么接住、下一首从哪个强拍或 drop 进；口播时音乐让路，停顿处可抬升并配画面重击。
- 音效必须对应画面动作。先从 earshot 找，找不到贴切的再用 Openverse 中的 Freesound 来源；记录外部音效的许可和署名。同一时刻避免堆太多层，教程录屏默认不加鼠标点击声。
- 混音交付目标：人声约 -16 LUFS，整片 -14 LUFS、真峰值不高于 -1 dBTP；以实测和试听验收。风格样片的不同响度不改变此目标。口播、BGM 或音效时间线变化后重混，避免预览仍用旧音轨。

## 审片与交付

- 每段截关键静帧并在浏览器完整播放，核对口播、字幕、画面、素材解码、切点、BGM 和音效。手机上检查文字大小和阅读时间。遇到黑屏、定格抽搐、空画面时先检查素材编码、速率和镜头交接。
- 默认交可编辑工程和预览，不默认上传本地原片、个人绝对路径、缓存或导出成片。明确要求导出后核对高清源、输出参数、音画时长和播放结果。
