# web-player 实现与复用指南

`web-player` 用浏览器解码素材，并在 Canvas 上按当前时间绘制镜头、字幕和动画。预览直接读取项目数据与音轨，修改后刷新页面即可审片；只有明确要求导出时，才逐帧取图并编码视频。

## 1. 文件如何配合

| 文件 | 职责 |
|---|---|
| [`模板/project.json`](模板/project.json) | 本期镜头 `shots`、显示字幕 `subs`、事件 `events`、音轨与素材路径 |
| [`模板/build.py`](模板/build.py) | 校验数据并生成 `data.js`、`sources.js`、`assets.js`；示例音轨只提供播放器时钟 |
| [`模板/scenes.js`](模板/scenes.js) | 按时间绘制各镜头内容；每期要替换示例画面 |
| [`模板/common.js`](模板/common.js) | 把镜头、字幕和场景合成一帧，提供基础绘制函数 |
| [`engine.js`](engine.js) | 素材视频池、Canvas 绘制、效果与精确取帧 |
| [`player.js`](player.js) | 以音轨为主时钟控制播放、暂停、拖动、镜头跳转、逐帧与倍速 |
| [`serve.py`](serve.py) | 本地 HTTP 服务、视频 Range 请求与高清素材映射 |
| [`export_mp4.py`](export_mp4.py) | 在明确要求导出后调用浏览器取帧并用 FFmpeg 编码 |

模板不是转写、口播剪接或混音工具。真实项目先在本期工程中完成这些步骤，再把最终镜头、字幕、事件和混音音轨填入 `project.json`。保留原录音与原始逐字时间，显示字幕单独整理；细则见 [口播与字幕](../editing/02-口播与字幕.md)。

## 2. 同一条时间线

浏览器的统一时钟来自 `project.json.audio` 指定的音轨。`shots` 必须从 0 开始、前后连续；`subs` 每条都落在对应镜头内且彼此不重叠；`events` 的时刻不能超出全片。`build.py` 会检查这些边界，生成供播放器读取的 JS 数据。

把口播中的 `[a,b]` 删除时，后续镜头、字幕和事件应整体前移 `b-a`；同时重建音轨。只删显示字幕不会剪掉声音，只改镜头长度也不会自动改变音轨。可以在本期工程维护源时间与成片时间的 `pieces` 映射，再统一生成 `project.json`；模板本身不提供口播剪接器。

视频素材的取帧时间一般为 `sourceIn + (t - shotStart) × rate`。画面函数传入的视频 `rate` 应与源时间推进速度一致；定格或素材播放完后用 `rate = 0` 保持最后一帧。预览倍速只改变主时钟的推进速度，不应在画面函数里再乘一次。

## 3. 播放和精确取帧

- 连续播放时，播放器跟随音轨时间推进，视频元素在容许范围内自由播放，出现漂移时才校正，避免每帧强制 seek 造成抖动。
- 拖动、逐帧和导出时，暂停视频，seek 到目标时间，等待目标帧就绪后再绘制。`renderAt(t)` 要能在不连续播放前提下重复得到同一画面。
- 动画位置、缩放、透明度只由时间 `t` 决定；随机效果固定种子。不要依赖上一帧状态、`Date.now()` 或自动播放的 CSS 动画，否则回拖和导出的结果会不同。
- 缓存画面可减少跳转时闪黑，也可能遮住素材解码失败。审片时必须查看真实切点，不用缓存帧当成素材正常的证据。

## 4. 修改后重建什么

| 修改内容 | 必要动作 |
|---|---|
| 字号、位置、裁切、素材取景或场景动效 | 改 `scenes.js`，刷新预览 |
| 字幕文字、断句或顿号空格 | 改字幕源，运行 `build.py`，刷新；原音轨不变 |
| 只换画面素材 | 改 `sources` 或本地高清映射；必要时重启服务 |
| 剪口播、补录、加停顿或变速 | 在本期工程重建统一时间线、字幕、事件和混音；再运行 `build.py` |
| 改 BGM 或音效 | 重新混音并刷新预览音轨 |
| 用户明确要求成片 | 用当前工程导出，核对高清源、倍速、音画时长与文件播放结果 |

`build.py` 只负责数据校验与生成 JS，不会自动转写、剪音频或混音。详细命令和导出参数见 [README](README.md)。

## 5. 便携素材与本地高清

共享工程引用相对 URL，例如 `media/08.mp4`。本机可以通过 `.local/media.json` 把同一 URL 映射到本地高清原片；映射目录被 Git 忽略，不写进共享 JS。修改映射后重启服务，逐项检查 `/__local_hd_status__`、响应头和实际素材。映射记录存在不等于每一份素材都是高清。

服务处理普通和后缀 Range 请求，使大视频可以拖动；要测试 seek，不能只看首页是否打开。若映射目标丢失，应明确报错，不能静默退回低清代理。截图里的文字模糊时，先判断源片、裁切放大、预览代理或输出分辨率哪一层造成问题；必要时高清重排并与原截图逐行比对。

## 6. 新项目检查顺序

1. 阅读 [通用剪辑规则](../editing/README.md) 与当期项目要求，明确原片、便携素材、预览和输出尺寸。
2. 用 `init_project.py` 创建不存在的新目录；先验证 6 秒示例能播放、拖动、跳镜头和逐帧。
3. 接入本期真实素材、混音和有使用权的字体，核对时长、画幅、帧率和素材解码。
4. 建立本期时间线，校对字幕并保留源时间；再实现镜头场景与必要动效。
5. 每次只重建受影响的数据或音轨，逐段浏览器审片；明确要求后才导出成片。

当前模板采用 1920×1080 横屏逻辑画布。把输出放大到 2560×1440 不会凭空增加文字细节；竖屏和原生 2K 需要分别适配布局、缓存和字体尺寸。真实 4K 素材的解码性能须在本期工程验证，不由 6 秒静音示例的测试结果保证。
